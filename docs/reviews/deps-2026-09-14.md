### 고친 것: `rustls-pemfile` 제거

넷 중 유일하게 우리가 직접 의존하던 것이다. 권고문이 말하듯 이 크레이트는 2025년 8월에 보관
처리됐고, **이미 트리에 있는 `rustls-pki-types` 의 같은 코드를 얇게 감싼 것**이다. PEM 파싱은
`rustls_pki_types::pem::PemObject` 로 바로 할 수 있고, 그 모듈은 기본 기능(`alloc`)에 들어 있어
새 의존성이 늘지 않는다. `rustls` 가 `pki_types` 를 다시 내보내므로 `use rustls::pki_types::…` 면 된다.

- 바꾼 곳: `crates/nl-io/src/httpd.rs` 의 `TlsAcceptor::from_pem`
- 지운 것: 워크스페이스와 `nl-io` 의 `rustls-pemfile` 의존성
- 확인: TLS 시험 4개 통과(잘못된 키·쓰레기 PEM·평문 요청 거부·https 왕복)

의존성이 하나 줄고 미유지보수 경고가 4건에서 3건이 됐다.

### 제안

**1. `tch`·`torch-sys`·`candle-core` 가 왜 들어오는지 확인할 것.**
`ureq` 2, `zip` 0.6/7.2, `safetensors` 0.3 의 유일한 유입 경로다. burn 의 선택적 백엔드가
기본으로 켜져 있다면 꺼서 중복 셋을 한꺼번에 없앨 수 있다. 빌드 시간과 공급망 표면이 함께 준다.
**이번에는 건드리지 않았다** — 엔진 담당자의 영역이고 기능에 영향이 갈 수 있다.

**2. `wgpu` 29/30 은 burn 을 기다린다.**
우리가 `wgpu = "29"` 를 올리면 burn 과 어긋난다. burn 이 wgpu 30 을 쓰는 판을 낼 때 함께 올리는 것이
맞다. 그 전까지는 장치 열거용 wgpu 와 렌더용 wgpu 가 따로 빌드된다.

**3. 워크스페이스 크레이트에 `publish = false` 를 붙일 것.**
지금은 `cargo deny` 가 우리 크레이트를 "발행 가능" 으로 보고 내부 `path` 의존성을 전부
와일드카드로 잡는다. 그래서 `deny.toml` 의 `wildcards` 를 `warn` 으로 낮춰 두었다.
`publish = false` 를 붙이면 `deny` 로 올려도 조용해지고, 실수로 crates.io 에 올리는 일도 막힌다.
크레이트마다 한 줄이라 이번 감사 범위 밖으로 두었다.

## 설정과 CI

- `deny.toml` 을 저장소 루트에 두었다. 각 항목에 왜 그 값인지 주석이 있다.
- CI 에 `audit` 잡을 더했다(`.github`·`.forgejo` 바이트 동일).
  - **라이선스와 출처는 실패로 다룬다.** 우리가 고르는 것이고 어기면 배포가 막힌다.
  - **advisory·중복 버전은 알리기만 한다**(`continue-on-error: true`). advisory 는 남이 공개하는
    순간 늘어나서, 우리가 한 줄도 안 고쳤는데 어제 초록이던 것이 오늘 빨강이 된다. 그런 실패가
    반복되면 결국 아무도 안 보게 된다. 사람이 보고 판단해 이 문서에 남기는 편이 낫다.
  - `cargo audit` 도 따로 돌린다. cargo-deny 와 겹치지만 둘 중 하나가 막혀도 나머지가 돈다.

## 다시 돌리는 법

```sh
cargo install cargo-audit cargo-deny --locked
cargo audit                    # 취약·미유지보수
cargo deny check               # 라이선스·advisory·중복·출처 전부
cargo deny check licenses      # 라이선스만 (CI 가 실패로 다루는 것)
cargo tree -i <크레이트>       # 무엇이 그것을 끌어오는지
```
