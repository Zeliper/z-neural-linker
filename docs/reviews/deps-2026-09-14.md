### 고친 것: `rustls-pemfile` 제거

넷 중 유일하게 우리가 직접 의존하던 것이다. 권고문이 말하듯 이 크레이트는 2025년 8월에 보관
처리됐고, **이미 트리에 있는 `rustls-pki-types` 의 같은 코드를 얇게 감싼 것**이다. PEM 파싱은
`rustls_pki_types::pem::PemObject` 로 바로 할 수 있고, 그 모듈은 기본 기능(`alloc`)에 들어 있어
새 의존성이 늘지 않는다. `rustls` 가 `pki_types` 를 다시 내보내므로 `use rustls::pki_types::…` 면 된다.

- 바꾼 곳: `crates/nl-io/src/httpd.rs` 의 `TlsAcceptor::from_pem`
- 지운 것: 워크스페이스와 `nl-io` 의 `rustls-pemfile` 의존성
- 확인: TLS 시험 4개 통과(잘못된 키·쓰레기 PEM·평문 요청 거부·https 왕복)

의존성이 하나 줄고 미유지보수 경고가 4건에서 3건이 됐다.

## 메이저 버전 중복

**세는 방법을 먼저 정해야 한다.** `cargo metadata` 나 `Cargo.lock` 을 그대로 세면 실제로 빌드되지
않는 것까지 들어와 숫자가 부풀려진다. 아래는 두 가지를 나눠 적는다.

| 기준 | 크레이트 수 | 메이저 중복 |
| --- | --- | --- |
| `Cargo.lock` / `cargo metadata` | 797 | 60종 |
| **실제 빌드 그래프** (`cargo tree -e normal --workspace`) | **474** | **28종** |

`cargo deny check bans` 는 앞쪽(잠금파일) 기준이라 56종을 센다. 그래서 이 검사는 경고로 둔다 —
숫자의 절반쯤이 빌드되지 않는 것이다.

### 잠금파일에만 있는 것 — `tch`·`torch-sys`·`candle-core`

`burn` 은 `burn-tch`·`burn-candle` 을 **optional** 로 선언하고 `tch`·`candle` 기능 뒤에 둔다.
우리는 `default-features = false` 에 `std, ndarray, wgpu, autodiff, vulkan` 만 켜므로 그 기능이 꺼져 있다.

카고는 기능이 꺼져 있어도 optional 의존성을 해석해 잠금파일에 적어 둔다(나중에 기능을 켜도 버전이
흔들리지 않게). 그래서 `Cargo.lock` 에는 남아 있지만 `cargo tree -e all -i tch` 는 **아무것도 찾지
못한다** — 어느 빌드 그래프에도 없다는 뜻이다.

**따라서 burn 의 백엔드 기능을 끄는 작업은 필요 없다.** 이전 판에서 `ureq` 2·`zip` 0.6/7.2·
`safetensors` 0.3 중복을 그렇게 없앨 수 있다고 적었는데, 그 셋은 애초에 빌드되지 않는다.
실제 빌드에서 각각 `ureq` 3.4.2, `zip` 6.0.0, `safetensors` 0.8.0 **한 버전씩**이다.

### `wgpu` 29 / 30 — 배포물에는 하나뿐이다

이전 판에서 "가장 큰 중복" 으로 적었는데 정확하지 않았다. **배포하는 바이너리에는 wgpu 29 하나만
들어간다.** 우리 `eframe` 은 `glow` 렌더러를 쓰고 `egui-wgpu` 는 켜지 않는다.

wgpu 30 이 나타나는 곳은 **개발 의존성 한 군데**다: `egui_kittest` 의 `wgpu` 기능(스냅샷 시험이
소프트웨어 어댑터로 그림을 그린다) → `eframe` → `egui-wgpu` → wgpu 30.

```
wgpu v30.0.1 ← egui-wgpu ← eframe ← egui_kittest [dev-dependencies] ← nl-app
```

그래서 `cargo test -p nl-app` 은 wgpu 두 판을 빌드하지만 `cargo build --release -p nl-runtime` 은
하나만 빌드한다. 시험 빌드 시간이 늘 뿐 배포물 크기와는 무관하다. burn 이 wgpu 30 을 쓰는 판을
낼 때 자연히 합쳐진다.

### 제안

**워크스페이스 크레이트의 `publish = false`** — 이전 판의 제안이었고 **이번에 반영했다**.
11개 크레이트(`crates/*` 9개 + `vseat` + `onnxgen`) 전부에 붙였고, 그 덕에 `deny.toml` 의
`wildcards` 를 `warn` 에서 `deny` 로 올렸다. 이제 crates.io 의 `foo = "*"` 가 들어오면 막힌다.
실수로 발행하는 일도 함께 막힌다.

## 설정과 CI

- `deny.toml` 을 저장소 루트에 두었다. 각 항목에 왜 그 값인지 주석이 있다.
  `wildcards = "deny"` 로 두되 워크스페이스 안 `path` 의존성은 봐준다(`allow-wildcard-paths`).
  그게 먹으려면 우리 크레이트에 `publish = false` 가 있어야 하고, 11개 전부에 붙어 있다.
- CI 에 `audit` 잡을 더했다(`.github`·`.forgejo` 바이트 동일).
  - **라이선스와 출처는 실패로 다룬다.** 우리가 고르는 것이고 어기면 배포가 막힌다.
  - **advisory·중복 버전은 알리기만 한다**(`continue-on-error: true`). advisory 는 남이 공개하는
    순간 늘어나서, 우리가 한 줄도 안 고쳤는데 어제 초록이던 것이 오늘 빨강이 된다. 그런 실패가
    반복되면 결국 아무도 안 보게 된다. 사람이 보고 판단해 이 문서에 남기는 편이 낫다.
  - `cargo audit` 도 따로 돌린다. cargo-deny 와 겹치지만 둘 중 하나가 막혀도 나머지가 돈다.

## 다시 돌리는 법

```sh
cargo install cargo-audit cargo-deny --locked
cargo audit                    # 취약·미유지보수
cargo deny check               # 라이선스·advisory·중복·출처 전부
cargo deny check licenses      # 라이선스만 (CI 가 실패로 다루는 것)
cargo tree -i <크레이트>       # 무엇이 그것을 끌어오는지
```
