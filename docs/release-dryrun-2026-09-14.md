## 사전 조건 (§1~§4)

체크리스트 본문 앞의 "첫 릴리스 전에 반드시 끝낼 것" 이다. 넷 다 **아직 안 되어 있다.**
이것이 정상이다 — 사람이 해야 하는 일이고, 문서의 목적은 잊지 않게 하는 것이다.

### §1 서명 키 — 도구는 동작한다, 키는 없다

```sh
cargo run -p nl-update --example nl-keygen -- keygen --out <임시> --name dryrun
```

10.7초. 비밀키와 공개키가 나왔고 권한이 문서가 적은 대로였다.

| 파일 | 권한 | 크기 |
| --- | --- | --- |
| `dryrun.key` | 0600 | 294 B |
| `dryrun.pub` | 0644 | 114 B |

도구가 끝에 `gh secret set MINISIGN_KEY < <키파일>` 을 그대로 찍어 준다. 문서와 도구 출력이
같은 명령을 말한다.

`packaging/keys/` 에는 `README.md` 만 있다. `.gitignore` 12행이 `packaging/keys/*.key` 를 막는다 —
문서가 "비밀키는 `.gitignore` 가 막는다" 고 한 것이 사실이다. **드라이런은 진짜 키를 만들지 않았다.**
`packaging/keys/` 에 키를 두는 것은 사람이 한 번만 하는 일이고, 임시로 만들어 두면 진짜 키로
오해될 수 있어서다.

### §2 빌더 공개키 — 비어 있다

`crates/nl-app/src/update_key.rs` 의 `PUBLIC_KEY` 가 `None` 이다. 따라서 `ENABLED` 가 `false` 이고
빌더는 업데이트를 **확인조차 하지 않는다.** 주석이 이유를 적어 두었다 — 검증할 수 없으면 아예 묻지
않는 쪽이 안전하다. 지금 릴리스를 내면 자동 업데이트가 꺼진 채로 나간다.

### §3 CI 러너 — 문서에 없던 항목이었다 (추가함)

워크플로는 `runs-on: ubuntu-latest` 하나로 Linux 네이티브와 Windows 크로스를 함께 만든다.
GitHub 사본과 Forgejo 사본은 **바이트 단위로 같다**(`diff -q` 로 확인). 러너 전제 조건이 체크리스트에
없어서 절을 새로 넣었다. 아래 "찾은 문제 3" 참고.

### §4 배포 서버 — 주소는 살아 있으나 내용이 없다

```sh
curl -sSfI https://updates.trustanc.dev/neural-linker/latest.json
```

DNS 는 풀리고 앞단이 응답하지만 **HTTP/2 503** 을 돌려준다. 아직 무엇도 올라가 있지 않다.
`nl-app` 의 `UPDATE_URL` 과 `nl-app/src/tools.rs` 의 `DEFAULT_MANIFEST_URL` 이 이 주소를 가리킨다.

## 체크리스트 수행

### ① 버전 올리기 · 검증

버전은 올리지 않았다(0.1.0 그대로). 검증만 두 번 돌렸다 — **한 번은 메인 병합 전, 한 번은 뒤.**
병합 전 실행 중에 메인으로 엔진 브랜치 전체(ONNX 내보내기·템플릿·`onnx-import` feature)와 io 의
`--log-json`·`pipeline.uit`·export 종단이 들어와(51개 파일, +9,320줄) 다시 돌렸다.

```sh
scripts/verify-all.sh
```

| 단계 | 병합 전 (`fbcc1df`) | 병합 후 (`a7a93a4`) |
| --- | ---: | ---: |
| 포맷 검사 | 3s · **실패** | 7s · 통과 |
| 클리피 | 12s | 283s |
| 테스트 | 114s | 1,640s |
| 릴리스 빌드 | 689s | 751s |
| 종단 시험 | 40s | 595s |
| **합계** | **858s · 실패 1건** | **3,277s · 전부 통과** |

병합 전의 포맷 실패는 `crates/nl-core/src/validate.rs:479` 한 자리였다. 내 변경과 무관했고 **메인
병합으로 사라졌다** — 앱 담당자가 고쳤다. 병합 뒤 수치가 크게 는 것은 크레이트가 늘어난 탓도 있지만,
같은 시각에 다른 워크트리에서 엔진 담당자의 전체 테스트가 돌아 CPU 를 나눠 쓴 영향이 크다.

병합 후 결과:

- 단위·통합 **794건 통과**
- 종단 **6건 통과** (병합 전에는 3건이었다. io 가 export 종단을 더했다)
- 클리피 경고 0

종단 시험은 샘플의 고정 포트(8799·8800)를 쓰지 않고 빈 포트로 옮겨 띄우므로, 같은 기계에서
다른 것이 돌고 있어도 통과한다. 규칙은 `scripts/README.md`.
