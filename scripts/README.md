# 검증 스크립트 규칙

이 폴더와 `packaging/` 의 스크립트는 **개발자 기계에서 다른 것과 나란히 돈다.** 다른 에이전트,
다른 워크트리, 사람이 손으로 띄워 둔 앱이 같은 시각에 같은 기계를 쓴다. 아래 세 가지는 그때
서로를 밟지 않기 위한 규칙이다. 실제로 밟아서 생긴 규칙이라 예외를 두지 않는다.

## 1. 고정 포트를 그대로 열지 않는다

샘플 프로젝트의 추론 API 는 고정 포트를 쓴다 — XOR 은 `127.0.0.1:8799`, CNN 은 `127.0.0.1:8800`.
문서에 적어 둘 주소가 매번 바뀌면 곤란하기 때문이다. **검증은 이 포트를 쓰지 않는다.**
프로젝트를 임시 폴더에 복사해 포트만 빈 포트로 바꾼 뒤 띄운다.

셸에서는 `packaging/lib.sh` 의 두 함수를 쓴다.

```sh
source packaging/lib.sh

cp 샘플.nlproj "$TMP/시험.nlproj"
PORT=$(nl_free_port)                          # 운영체제에게 빈 포트를 받는다
ADDR=$(nl_rebind_project "$TMP/시험.nlproj" "$PORT")   # 파일을 제자리에서 고친다
```

`nl_rebind_project` 는 바꿀 주소를 못 찾으면 **실패한다.** 조용히 넘어가면 고정 포트로 돌아가
버리고, 그러면 이 규칙이 있으나 마나이기 때문이다. 같은 파일에 두 번 부르면 두 번째가 실패한다 —
이미 바뀐 파일에는 고정 주소가 없기 때문이다. 원본을 복사해 한 번만 부르라.

러스트 종단 시험(`crates/nl-cli/tests/e2e.rs`)은 같은 일을 `rebind_http_server(&proj, 원래주소)`
로 한다. 세 시험 모두 이것을 거친다.

## 2. 산출물 폴더에 pid 를 붙인다

로그·작업 폴더·`UITEST_DIR` 은 **항상** `$$`(pid)나 `mktemp -d` 로 다른 실행과 갈라 둔다.
같은 초에 두 번 돌아도 겹치지 않아야 한다.

```sh
OUT="dist-local/verify/$(date +%Y%m%d-%H%M%S)-$$"
UITEST_DIR="${UITEST_DIR:-/tmp/uitest-verify-$USER-$$}"
```

시각만 붙이면 모자란다. 두 사람이 같은 초에 시작하면 같은 폴더에 로그를 섞어 쓴다.

## 3. 자기가 띄운 프로세스만 죽인다

정리할 때 **이름으로 찾아 죽이지 않는다.** 띄울 때 pid 를 적어 두고 그 pid 만 죽인다.

```sh
./내앱 ... & echo $! > "$TMP/app.pid"
...
kill "$(cat "$TMP/app.pid")" 2>/dev/null || true
```

이름으로 찾으면 남의 것을 죽인다. 실제로 그렇게 옆 세션의 30분짜리 부하 시험을 19분에서
끊어 먹었다. 포트를 잡고 있는 프로세스도 마찬가지다 — **포트가 막혔다는 것은 남이 쓰고 있다는
뜻이지 찌꺼기라는 뜻이 아니다.** 막혔으면 죽이지 말고 1번 규칙대로 다른 포트로 비켜라.

pid 파일을 쓸 수 없어 이름으로 골라야 한다면, 자기 실행에만 있는 표식을 함께 확인한다.
`verify-all.sh` 의 `cleanup_gui` 가 그 예다 — `pgrep -x nl-app` 로 고른 뒤 그 프로세스의
`UITEST_DIR` 환경 변수가 자기 것과 같을 때만 죽인다.

`pkill -f`/`pgrep -f` 는 쓰지 않는다. 명령줄 일부를 넣으면 **자기 자신에게도 걸려** 호출한
셸이 함께 죽는다. `pgrep -x` 로 이름이 정확히 맞는 것만 고른다.

## 4. 성능 수치로 빌드를 세우지 않는다

`scripts/bench.sh` 는 느려진 항목을 표로 보여 주지만 **종료 코드는 늘 0** 이다. 이 기계는 다른
에이전트·워크트리와 함께 쓰고 부하가 2 에서 55 까지 흔들려서, 같은 코드가 세 배 차이로 찍힌다.
그런 숫자로 CI 를 빨갛게 만들면 사람이 표를 안 보게 된다. JSON 에 `load1` 을 함께 적으니
비교할 때 부하부터 보라 — 크게 다르면 그 줄은 의미가 없다.
