# nl-cli

`nl` — GUI 없이 Neural Linker 프로젝트를 다루는 명령줄 도구.

**실행 파일 이름은 `nl` 이다** (크레이트 이름과 다르다). 스크립트와 CI 에서 쓰라고 만든 것이라
출력은 사람이 읽기 좋게, **종료 코드는 기계가 읽기 좋게** 둔다.

| 코드 | 뜻 |
| --- | --- |
| 0 | 성공 |
| 1 | 명령이 문제를 찾음 (검증 오류·학습 실패·실행 중 오류) |
| 2 | 인자나 환경 문제 |

사용자 관점 설명과 예시는 [`docs/GUIDE.md`](../../docs/GUIDE.md) 의 "명령줄 `nl`" 절에 있다.

## 모듈 지도

| 파일 | 하는 일 |
| --- | --- |
| `main.rs` | clap 정의와 분기. 새 명령은 여기 열거형에 더한다 |
| `common.rs` | 프로젝트 읽기·원자적 쓰기, 이름/id 로 찾기, 장치 해석, 터미널 색, TLS 주입 |
| `inspect.rs` | 프로젝트 내용·검증 결과. 다입출력 모델이면 입출력 **순서 표**도 보여 준다 |
| `devices.rs` | 쓸 수 있는 장치 목록. `--probe` 면 실제로 작은 연산을 돌려 본다 |
| `train.rs` | 헤드리스 학습. 끝나면 실행 기록과 가중치 경로를 프로젝트에 적는다 |
| `infer.rs` | 모델 하나에 값·이미지·CSV 를 넣어 결과를 JSON 으로 |
| `run.rs` | 파이프라인을 헤드리스로 돌리고 이벤트를 찍는다 |
| `record.rs` | 화면을 찍어 학습용 폴더로. 라벨은 표준 입력 한 줄(숫자) |
| `build.rs` | 프로젝트 → `.nlapp` 번들 → 런타임 첨부 → 배포 아카이브 |
| `tlscert.rs` | `HttpServer` 노드용 자체 서명 인증서 만들기 |

`tests/e2e.rs` 는 종단 시나리오 넷을 담는다 (아래 참조).

## 명령

```
nl inspect <프로젝트>                  내용과 검증 결과
nl devices [--probe]                   장치 목록
nl train <프로젝트> --model <이름>     학습하고 프로젝트에 적는다
nl infer <프로젝트> --model <이름>     --input / --image / --csv
nl run <프로젝트>                      파이프라인을 헤드리스로
nl record <출력 폴더>                  화면 녹화
nl build <프로젝트>                    배포판
nl tls-cert <폴더>                     자체 서명 인증서
nl sample <출력> [--kind xor|cnn]      샘플 프로젝트
```

모델·데이터셋·파이프라인은 **이름으로도 id 앞부분으로도** 지목할 수 있다.

`run` 과 `build` 는 `--tls-cert`/`--tls-key` 로 `HttpServer` 노드를 https 로 열 수 있다.
`--http-node <이름>` 으로 한 노드만 고를 수도 있다. **프로젝트 파일은 바뀌지 않는다** — 이번
실행에만 붙으므로 인증서 경로가 실수로 저장소에 들어가지 않는다.

## 보안 규칙

실제 방어선은 `nl-io` 에 있다. 여기서는 명령줄이 그 규칙을 어떻게 노출하는지만 적는다.
자세한 것은 [`crates/nl-io/README.md`](../nl-io/README.md).

- **입력 무장은 opt-in** — `nl run --arm-input` 없이는 마우스·키보드 싱크가 로그만 남긴다.
  `nl build --arm-input` 없이 만든 배포판도 마찬가지다.
- **토큰** — `HttpServer` 노드의 토큰이 없으면 루프백에만 열린다. 배포판에서는
  `NL_HTTP_TOKEN` 또는 `NL_HTTP_TOKEN_<포트>` 로 실행 환경에서 새로 준다.
- **TLS** — `nl tls-cert` 가 만드는 것은 **자체 서명** 인증서다. 받는 쪽에 직접 심어 줄 수 있는
  자리(사내망·시험)에서 쓴다. `curl` 은 `--cacert` 가 필요하다. 공개 서비스에는 제대로 발급받은
  인증서를 같은 자리에 놓으면 된다.
- **개인키** — 유닉스에서는 0600 으로 쓴다. Windows 에는 권한 비트가 없어 그렇게 하지 못하고,
  출력이 그 사실을 알린다. `certs/` 를 `.gitignore` 에 넣어라.
- **인증서는 번들에 담지 않는다** — `nl build --tls-cert` 는 경로만 적는다. 개인키가 든 `.nlapp`
  은 그 자체가 유출이다. 배포 앱은 작업 폴더 다음에 **실행 파일이 있는 폴더**에서 찾는다.
- **경로 담장** — `--tls-cert`/`--tls-key` 는 프로젝트 폴더 기준 상대 경로여야 한다. 밖을 가리키거나
  파일이 없으면 **실행 전에** 거절한다. 배포판을 만들고 나서 켤 때 알게 되면 늦다.

## 알려진 한계

- **다출력 모델은 Output 노드 이름이 순서를 정한다.** 페이로드 출력 필드와 이름으로 맞추지 않고
  순서로 맞춘다. 이름을 비워 두면 필드가 뒤바뀔 수 있다. `nl inspect` 가 그 순서를 표로 보여 주고,
  이름이 없거나 개수가 어긋나면 색으로 짚는다.
- **학습은 첫 Output 만 손실·지표에 쓴다.** 나머지는 추론에서만 쓰인다. `nl inspect` 가 알린다.
- **다입력 모델의 CSV** 는 `input_cols` 를 Input 노드 순서대로 앞에서부터 잘라 넣는다.
  샘플당 원소 수가 Input 원소 수의 합과 같아야 한다.
- `nl record` 는 화면 세션이 있어야 한다. 헤드리스에서는 캡처기를 열지 못한다.
- `nl build --target windows` 는 `cargo-xwin` 과 Windows 런타임 바이너리가 있어야 한다.

## 종단 시나리오

`tests/e2e.rs` 에 넷이 있다. 무겁고 런타임 바이너리를 먼저 빌드해야 해서 **`NL_E2E=1` 일 때만**
돈다. 평소 `cargo test` 에서는 건너뛴다는 줄만 찍고 통과한다.

| 시나리오 | 확인하는 것 |
| --- | --- |
| XOR 배포판 | `sample → train → infer → build` → 배포판을 띄워 HTTP 로 추론까지 |
| CNN 이미지 | 이진 이미지 본문과 라벨 디코드 체인. PNG 를 POST 해서 분류 결과 |
| TLS | `tls-cert → run --tls-cert` → `curl -k` 로 https 200, 평문 요청은 거부 |
| 다입력·다출력 | Input 2개·Output 2개 모델을 학습·빌드 → 객체와 배열 두 형식으로 POST → 같은 객체 응답 |

TLS 와 다입출력 시나리오는 빈 포트를 받아 쓴다. 고정 포트를 쓰면 나란히 돌 때 서로 뺏는다.

```sh
cargo build --release -p nl-runtime
NL_E2E=1 cargo test -p nl-cli --test e2e -- --nocapture
```

런타임은 이 순서로 찾는다: `NL_RUNTIME` 환경 변수 → `CARGO_BIN_EXE_nl-runtime` →
`target/release/nl-runtime` → `target/debug/nl-runtime`.

## 시험 게이트

| 변수 | 없으면 | 켜면 |
| --- | --- | --- |
| `NL_E2E=1` | 종단 시험 넷을 건너뛴다 | 학습·빌드·배포판 실행까지 돈다 |
| `NL_RUNTIME` | 표준 위치에서 런타임을 찾는다 | 그 경로의 런타임을 쓴다 |
| `NL_HTTP_TOKEN[_<포트>]` | 프로젝트에 적힌 토큰 | 그것을 덮어쓴다 |
| `NO_COLOR` | 터미널이면 색을 쓴다 | 색을 끈다 (파이프로 넘길 때 제어문자가 섞이지 않게) |

TLS 시나리오는 `curl` 이 있어야 한다. 없으면 실패로 알린다 — 조용히 건너뛰면 https 왕복을
확인하지 않은 채 통과해 버린다.
